## 3. The two reconciliations

### 3.1 The z coordinate's provenance (correction)

Section 3 of the M6-D record states, from the extracted template, that the hero template root's default transform is the identity at (0, 0, 0) and that the observed z is not that default. The authored brick (F1) carries **no** transform property for Agent48 at all; the only authored transform in the brick is the spawn's, which the hero never carried (F3, F4). So z = −1.539356 is authored nowhere in the brick or in the template root, and the phrase "authored z" in M6-D record section 14 and in the roadmap summary was wrong. **Corrected wording: an observed z offset of −1.539356 on Agent48's own world and parent-relative translation; origin unresolved (H2).** The raw values are unchanged; a clean cache flag, equal world and parent-relative translations and the repetition under a new generation show only that the value is stable, not how it arose. No physics, grounding or template inheritance is inferred.

## 4. The stock spawn and the application path: what the sources establish

- **The selected spawn of the tested Paris entry is not established** by source or by runtime: the location brick holds no spawn; the three mission bricks hold 9 spawns (one `m_bDefaultHeroSpawn` true at (10.214, −10.205, −1.267), none preferred, none with a player id, set id, hero reference or repository id); the hero's observed position (−83.74, 14.70) is 94 m from that default spawn and matches no authored spawn — the intro / planning-entry placement path moved it (M6-D track B extract 9). [S]; the engine's reading of them [U1]
- **Is that knowledge required for the next operation?** No. The M6 exit criterion is an externally driven representation. ## 5. The three options compared

| Criterion | **A** — one more read-only control | **B** — a bounded, reversible transform change of Agent48 | **C** — applying the hero-spawn mechanism |
|---|---|---|---|
| The missing observation | which runtime entity carries the authored spawn transform (F4); Agent47's own spawn beside Agent48's | none: it measures U2 directly | the selection / application behaviour (U1) |
| Competing hypotheses it discriminates | where the spawn's authored position lives; whether the stock spawn differs from Agent48's by the default / preferred flags alone | whether the raw transform of the second entity changes on command and is restored by a reversal; whether something restores it (physics, controller) | whether the engine will place a second hero at all |
| Does the result change the next decision? | **No**: moving Agent48 does not depend on the spawn's position or on which stock spawn placed Agent47; the one open fact (F4) is a documentation gap, not a safety or identity gap | yes: changed → the exit criterion's first half holds; unchanged / reverted → the next design is physics- or controller-side | yes, but every answer carries side effects |
| Mutation surface | none | one virtual call on one entity (its transform); the preimage saved; one reversal | content defaults or engine-internal calls; may select the local player, rebind the main camera and input, replace the existing hero, alter global spawn preference |
| Target identity | — | Agent48 resolved afresh by brick + authored id + generation, proven distinct from the local hero and absent from the registry on the applying frame | the engine chooses |
| Reversibility | — | the saved full preimage restored by a separate command; gameplay consequences unknown | poor: a spawn selection is not undone by a value write |
| Proximity to the M6 exit | zero | the exit's first half ("externally driven representation": a transform driven from outside) | not required by the exit |
| Information gained | small, already mostly authored defaults | large: U2, part of U3 | large but entangled with ownership |

**Decision: Option B.** Option A is not recommended: repeating known authored defaults, or locating the authored spawn transform at runtime, affects neither identity, nor the coordinate interpretation of Agent48 (whose z is unresolved either way), nor the safety of the transform call, nor the experiment's outcome. Option C is compared only to show it is not necessary and is broader and less reversible than B. B is not chosen to avoid another inert run; it is chosen because the exit criterion's first open question (can the representation be driven from outside?) is answered only by driving it, and every prerequisite the M5 contract demands for an effectful operation is already in place.

**The smallest blocker:** none architectural. The unknowns B measures (U2) are its purpose, not its blockers. The one unprecedented element — the setter on a hero that no spawn placed — carries an uncharacterized crash risk that upstream precedent (the setter on the local hero, routinely) reduces but does not remove; it is accepted only for an attended, single-shot, operator-confirmed experiment with the full rollback plan, as M6-C3 and M6-D1b were.

## 6. The preferred next experiment: M6-F — one bounded, reversible transform change of Agent48 (research only; not implemented)

### 6.1 The operation [S] / [U]

`candidate.transform.set` version 1 (name indicative): on the applying frame, inside the dispatch, for the candidate resolved afresh (6.3): read the preimage (6.4) → evaluate the gate (6.5) → **one** call `s_Spatial->SetObjectToWorldMatrixFromEditor(s_Target)` where `s_Target` is the preimage world matrix with only `Trans` replaced by preimage `Trans` + the bounded displacement (6.6) → same-frame read-back of `m_mTransform`, `m_bWorldTransformDirty`, `m_vObjectToParentRotation` / `Translation` by field → classify → return. World space by the method's name and by every upstream use (F8). Not a generic teleport: the entity is fixed by the compiled candidate identity, the displacement is a compiled bound, the local hero is refused as a target by identity, no other entity is addressable. Whether the call updates the parent-relative fields, fires `m_pTransformChangeCallBackEvent`, moves a physics capsule or is undone by a controller on the next frame is **U2**, read back, never assumed.

### 6.2 Threading, lifetime and the one call site [S]

The scheduler's frame-thread dispatch (the M5 `first_thread_id` check); the entity pointer and its `ZSpatialEntity` interface obtained on that frame through the existing `Lookup` and `QueryInterface`, used within the dispatch and discarded; no pointer leaves the frame; exactly one `SetObjectToWorldMatrixFromEditor` call site in the Relay sources (a source gate, as the one `SetOutfit->Call` site is today); the fault guard around the dispatch; a fault → `failed`, `effect uncertain`, the run stops.

### 6.3 Target identity preconditions (all on the applying frame) [S] + [R]

The brick present on a complete scan; the candidate resolved through the brick's template factory with `in_range`; `cand_hitman5`; `cand_id_match` (the type carries the authored id `feede715906f747f`); `cand_distinct` by pointer inequality with registry slot 0's hero AND the authored ids differ AND the owning brick is the hitmen brick; the registry slots read on the frame and the candidate in **none** of them; the `ZSpatialEntity` interface pointer of the candidate ≠ the local hero's; the expected generation equal at receipt, cached and fresh (M5 rules 1–4). Any failure → `precondition_failed` with the reason, nothing called.

### 6.4 The preimage and lossless restoration [S]

Captured natively before the call: `m_mTransform` as 12 IEEE-754 floats (XAxis, YAxis, ZAxis, Trans), `m_vObjectToParentRotation` (4), `m_vObjectToParentTranslation` (3), `m_bWorldTransformDirty`, `m_eidParent`'s authored id, the entity flags; returned in the result as exact 8-hex-digit float words (19 words ≈ 170 bytes, within the line bound) [reconciled in 12.3: 170 characters exceed the 128-byte text-field bound; the words travel as two fields, a 12-word world group and a 7-word parent-relative group] beside the 7-significant-digit text used for human comparison. **The existing inspection text (7 significant digits) is adequate for comparison only, not as a restoration source**: the reversal's target is the exact preimage words from the journaled result. A preimage read under a SET dirty flag is refused (`preimage_dirty`): the cache would not be the current world transform and the restoration target would be unknown.

### 6.5 The gate (reused from M5, extended) [S]

M5 C-2 rules 1–11 (generation ×3, predicate and stability, contract evidence, epoch, scene type / stage / resource), 17 (link generation re-read), thread, busy, the effectful setting, one-shot effectful arming with the telemetry attestation and ownership evidence, `:token_verified`; plus 6.3, `preimage_dirty`, and **`expect_current`** = the 7-digit world translation text of the candidate from a recent inspection (≤ 60 s, the same generation; the reversal binding of the pre-C3 hardening) which must equal the preimage's rendering [reconciled in 12.3 and 12.5: seven-digit text is not an adequate authority for the expected current state; the expectation is the exact word groups of a recent exact inspection, compared bit for bit on the applying frame]. Target ≠ current. Refusals are reported with their reason and nothing is called.

### 6.6 The displacement and its safety [I]

A single translation-only change: `Trans.z += 0.25 m` (rotation and axes untouched), i.e. from (0, 0, −1.539356) to (0, 0, −1.289356), compiled, not a parameter. Why vertical and small: no navmesh or collision information exists for the template origin, so a horizontal move cannot be shown free; ~~a 0.25 m lift from the position the entity already occupies stays inside the volume it already occupies above its base~~ [withdrawn in 12.2: translating a body upward introduces a new volume above its previous top; no clearance, collision, room-boundary or streaming guarantee follows from the displacement being small]; it is large against the 7-digit comparison and the 1·10⁻⁵ drift seen on the local hero, ~~and small against any room or streaming boundary~~ [withdrawn in 12.2]. ~~Safety is established by~~ [reworded in 12.2: the lift is a limited experimental exposure with unknown engine consequences; what the following elements establish is containment, not collision-proven safety]: the target entity being the one no system has moved in 28 s and across a restart (F3), the preimage and the bound being compiled, the single call, the read-backs, and the stop rules — not by assuming the entity is unsimulated. No raycast is added (the collision manager's `RayCastClosestHit` exists upstream but is another unverified engine call; not needed for a 0.25 m lift).

### 6.7 Read-backs, effect vocabulary and later observation [S] + design

Same-frame post-call read (inside the dispatch): `effect changed` when `m_mTransform.Trans` equals the target exactly; `unchanged` when it equals the preimage; `uncertain` otherwise or on a fault. The next frames: `relay.inspect.candidate/1` as the later-frame read (one command per frame; issued by the operator ≥ 1 s and ≥ 10 s later), with the cross-check classifying **`held`** (the target persists), **`reverted`** (the preimage is back: something restored it), **`drifted`** (neither), ~~by exact text comparison~~ [reconciled in 12.8: by exact word comparison of the later exact snapshot, with the declared tolerance classes `near_target` / `near_baseline` and an `indeterminate` class for a dirty cache; the later inspection is `relay.inspect.candidate_transform/1`], plus the dirty flag, the parent-relative fields and the local hero's unchanged transform on the same frames. None of these is a failure; each is the finding the experiment exists to produce.

### 6.8 Visual corroboration [T] bounded

No Editor or FreeCam interaction. If the operator can see the entity from a safe position (unknown: the template origin's location in Paris is not established), the operator's statement before and after is journaled as testimony; otherwise visual existence stays M6-E's question. The exit criterion speaks of a driven representation, not of pixels. [Reconciled in 12.2: the first lift is a transform-control experiment, not a visual-presence experiment; it leaves x and y unchanged; a successful read-back is never redefined as visual confirmation; the runbook must state from evidence whether a view of the test location exists, or label the run potentially telemetry-only.]

### 6.9 Failure containment [S] (M5 section 9 applied)

Fault during the call → `failed`, `uncertain`, stop. Link loss / terminal timeout → `unknown`; inspect before anything. Scene transition → the gate refuses what it can see; `applied_at_transition_edge` otherwise. Process termination (incl. the SDK's pool-exhaustion exit) → unknown, evidence preserved, no retry. Physics or a controller restoring or moving the entity → a classified later-frame finding, never corrected. Dirty cache after the call → recorded ~~; a later inspection decides~~ [reconciled in 12.8: a dirty post-call cache is an indeterminate observation, never `changed` or `unchanged`; a later read-only inspection may clarify it without a further write]. ~~State drift between the preimage and the call cannot occur (same frame, same dispatch).~~ [withdrawn in 12.2: one frame callback avoids intervening Relay dispatches but is not a synchronization guarantee against engine threads, synchronous callbacks, parent changes or later-in-frame events; the fresh checks and the post-call evidence are reused without a promise of atomicity]. No automatic retry, no automatic reversal.

### 6.10 Reversal [S]

A separate command (`candidate.transform.set` with target = the exact preimage words, `expect_current` = the post-change text [reconciled in 12.5: the restore mode's expectation is the exact word groups of a later exact inspection, and its target is the journaled preimage world group bound to the original command and to the native operation record]), built from the journaled result, bound to a recent inspection, under its own arming; the full gate again; it restores the **value** [reconciled in 12.6: it passes the saved world matrix through the same single setter; the parent-relative fields, the parent identity and the dirty flag are re-observed, never assigned; world, parent-relative, exact and numerical restoration are separate result facts]; gameplay consequences, if any system reacted, are not restored and are unknown unless observed. If the later-frame read already shows `reverted`, the reversal is refused ~~by `expect_current_mismatch` and nothing is written~~ [reconciled in 12.9: the planner records that no explicit restoration call is needed and does not submit one just to obtain a refusal].

## 8. Required evidence (observation, success, refusal, abort, restoration)

Per command: the journal ladder, the native `applying` / `applied` lines, the result with the preimage words, the post-call read, the effect; the candidate inspection before (the `expect_current` source) and after (≥ 1 s, ≥ 10 s), decoded separately; the local hero's transform unchanged on every frame; the registry slots unchanged; the native log 0 FAULT; the reversal's own ladder and read-backs; the telemetry reconciliation and replay (the final capture taken AFTER the game exit); the full restoration with exact timestamps; every historical manifest against the explicit exceptions. Success = `changed` on the applying frame AND `held` on the later frame AND the reversal `changed` back AND the local hero untouched. `reverted` or `unchanged` is a valid, reported outcome (not success, not failure of the instrumentation). Refusals and aborts are evidence of the gate, never retried.

The review accepted the direction of Option B and authorized the offline implementation and validation of M6-F, subject to the explicit reconciliations below. They are made in this documentation-only commit before any code; the marked sentences of sections 6.4–6.10 are superseded exactly where marked. Section 11's "not authorized" list is superseded for the M6-F1a authorization only by 12.13. Nothing here is unqualified acceptance of the design's safety, atomicity or lossless-restoration claims: the accepted objective is an implementation that can test those unknowns honestly.

### 12.1 What stays fixed

The working name **M6-F**; the compiled displacement **+0.25f on world z** as the first implementation; the compiled target **brick `007c57a6ea581f8c`, authored entity `feede715906f747f`** (Agent48); the one setter `ZSpatialEntity::SetObjectToWorldMatrixFromEditor(SMatrix)`; the M5 effectful contract (token-verified trust, fresh operator evidence, one-shot arming, TTL, queue / dedup, the checked audit path, same-frame fresh generation checks, the transition epoch, the predicate and stability rules, the thread check, effectful default-off) reused and **extended explicitly** for this operation. No arbitrary location, direction, rotation, scale, distance, entity, pointer or function name may be supplied by a peer.

### 12.2 What this experiment proves — withdrawn and reworded statements

- **Withdrawn** (6.6): "a 0.25 m lift … stays inside the volume it already occupies". Translating a body upward introduces a new volume above its previous top. No clearance, collision, room-boundary or streaming guarantee follows from the displacement being small. The lift is **a limited experimental exposure with unknown engine consequences**, not collision-proven safety.
- **Withdrawn** (6.9): "state drift between the preimage and the call cannot occur". Execution inside one frame callback avoids intervening Relay frame dispatches; it is **not** a synchronization guarantee against engine threads, synchronous callbacks, parent changes or later-in-frame events. The fresh checks and the post-call evidence are reused without a promise of atomicity.
- **Reworded** (6.8): the first lift is a **transform-control experiment**, not a guaranteed visual-presence experiment. It leaves Agent48's x / y unchanged. A successful read-back is never redefined as visual confirmation. The M6-F1b runbook must state, from actual evidence, whether normal gameplay and camera positioning can provide a view of the test location; if unknown or impractical, the run is labelled **potentially telemetry-only** and the smallest subsequent visual-placement question is stated. No enlarged displacement, no FreeCam / Editor, no raycast, no mandatory further inert run; any placement / location capability needs its own reviewed contract.

### 12.3 Exact snapshots and the bounded wire representation

- **Canonical float word**: the IEEE-754 binary32 bit pattern of one stored float, as exactly 8 lowercase hex digits, most significant nibble first (`-1.539356f` = `bfc50a7e`; `+0.0f` = `00000000`; `-0.0f` = `80000000`). The conversion is a bit copy in both directions (native `memcpy`; BEAM `<<w::32>>` ↔ `<<f::float-32>>`), never through rounded text.
- **Groups** (one text field each, comma-separated, no spaces): the **world group `W12`** = `m_mTransform` in its declared `SMatrix43` order `XAxis.x,y,z, YAxis.x,y,z, ZAxis.x,y,z, Trans.x,y,z` (12 × 8 + 11 = **107 bytes**); the **parent-relative group `L7`** = `m_vObjectToParentTranslation.x,y,z, m_vObjectToParentRotation.x,y,z,w` (7 × 8 + 6 = **62 bytes**). Nineteen words with separators need 170 characters and cannot be one 128-byte text field; the two groups fit individually. Structure padding is never serialized.
- **Validation** (both sides, before any use): exact word count, exactly 8 hex digits per word, every word **finite** (exponent field ≠ `0xff`: NaN and ±Inf refused); signed zero preserved as evidence (`00000000` ≠ `80000000`, both finite). A group that fails decodes to `:invalid`, never to a partial value.
- **Human text companions** (`*_world`, `*_local`: 7 significant digits, `%.7g`, the M6-D1a grammar) are for reading only; **no decision, expectation, binding or equality claim is made from them**. Two floats with the same 7-digit rendering and different bits are different states (`-1.539356f` `bfc50a7e` and the next float up `bfc50a7f` both render `-1.539356`; the offline matrix carries exactly this pair).
- **Round trips tested**: native encode → JSON → BEAM decode → journal → BEAM request reconstruction → native decode → the same 32-bit words; the actual encoded bytes are measured against the 4,096-byte line and the 128-byte text-field bounds; the 48-entry cap is preserved.
- **Result capacity**: before invocation the native side measures the **worst case** of the mandatory result (identity, exact preimage, requested and postimage groups at their fixed lengths, the generations at 64 bytes, the reason at 200 bytes) against the line bound and refuses with `result_capacity` when a mandatory result could not be represented; a mandatory field is never truncated and the command never proceeds "as though complete". Fault-related missing evidence stays explicitly unavailable or unknown.

### 12.5 The narrow effectful request: `candidate.transform.set` v1

| Parameter | Type | Mode |
|---|---|---|
| `mode` | `"lift"` or `"restore"` | both |
| `expect_world` | `W12` | both: the exact world group of a recent, completed `relay.inspect.candidate_transform/1` on this link, adapter and generation |
| `expect_local` | `L7` | both: the same inspection's parent-relative group |
| `expect_parent` | 16 lowercase hex | both: the same inspection's parent id |
| `target_world` | `W12` | restore only: the journaled preimage world group of the original forward command (refused if present on a lift) |
| `restore_of` | UUID v4 | restore only: the original forward command's id (refused if present on a lift) |
| precondition `mission_generation` | text | mandatory, both |

- **Forward (`lift`)**: the target is computed **natively** from the freshly validated snapshot: every word of the preimage world group copied bit for bit, `Trans.z` replaced by `preimage.Trans.z + 0.25f` in binary32 arithmetic (round to nearest). No target may be supplied.
- **Restore**: `target_world` must equal, bit for bit, the **native operation record's** remembered preimage world group (plain copied values, never engine pointers) of the operation `restore_of` names; it is also bound by BEAM to the journal (12.9). A supplied matrix is therefore never a way past the compiled movement restriction.
- **Decode-time refusals** (answerable, nothing scheduled): the effectful setting off; an unknown or missing parameter; a malformed, miscounted or non-finite group; a lift carrying `target_world` or `restore_of`; a restore lacking either; a restore whose `target_world` equals `expect_world` (already at baseline: a no-op is not an effectful command); the precondition missing.
- **Applying-frame gate** (all on the applying frame; every failure reported with its reasons and nothing asked of the engine; `unavailable` for a reason that means "could not establish", `precondition_failed` otherwise): the M5 common rules (expected / at-receipt / cached / fresh generations present and equal; playing now and on the previous frame; the stable interval and frame count since the rise; a contract start seen for the generation and no end; scene available, loaded, stage 8, type mission, the rise's resource; epoch unchanged since receipt; the link generation re-read before the call; the frame thread; the fault latch) **plus the transform rules**: `candidate_brick_absent`, `candidate_unresolved`, `candidate_index_not_in_range`, `candidate_not_hitman5`, `candidate_id_mismatch`, `candidate_owner_mismatch` (the owning brick is not the compiled brick), `candidate_not_distinct` (the lookup returned the local hero), `candidate_spatial_unavailable`, `candidate_spatial_not_distinct`, `candidate_in_registry` (any slot classified `candidate`, or any populated slot `inconclusive`), `registry_unreadable`, `hero_control_unavailable` (the local hero's snapshot could not be read), `preimage_dirty`, `expect_world_mismatch`, `expect_local_mismatch`, `expect_parent_mismatch`, `target_equals_current`, `target_not_finite`, `result_capacity`, and for the budget and record: `budget_exhausted`, `operation_record_missing`, `operation_record_mismatch`, `operation_record_invalidated`, `operation_effect_not_changed`, `restore_target_mismatch`, `restore_link_changed`, `restore_generation_changed`, `current_not_postimage`, `already_restored`.

### 12.6 Budget, operation record and invalidation

- **Native ledger** (`TransformApply::Ledger`, plain values held by the scheduler for the life of the process): `forward_budget` starts at **1** and is consumed when the forward setter call is **made** (after the pre-call line was accepted), never by a refusal, so a refused lift may be re-issued and an invoked one may not; the **operation record** holds the forward command id, the link generation, the mission generation, the 19 preimage words, the preimage parent, the requested world group, the 19 postimage words and the effect; state `none → forward_invoked → restored | invalidated`.
- **Restore eligibility** (native, before the one setter call): a record in `forward_invoked` with effect `changed`; `restore_of` equal to the record's id; the current link generation equal to the record's (a reconnect invalidates); the fresh mission generation equal to the record's; `target_world` equal to the remembered preimage world group; the fresh world group equal to the remembered **postimage** world group (`current_not_postimage` otherwise); one restore per forward (`already_restored`).
- **Invalidation** (no new lift, no guessed restore): a fault latch; a forward effect `uncertain`; a lost record (process restart); a link generation change; a mission generation change; an unexpected control change on the forward frame (12.8). Refusal is preferred to reconstructing missing authority heuristically. The budget's lifetime is the process; a BEAM restart does not re-grant it.
- **BEAM budget** (defence in depth, `Command.Authority`): one lift per authority process lifetime once a lift command has been accepted and its terminal is not a verified non-application (`rejected`, `expired`, `precondition_failed`, `unavailable` leave the budget; `applied`, `failed`, `unknown` and an in-flight lift consume it): `:transform_budget_exhausted`. A restore is issuable only through the planner-bound facade (12.9), as a distinct, separately armed command; it is never an automatic cleanup handler. Fresh command ids and repeated one-shot arming cannot produce a series of lifts.

### 12.7 Invocation, the pre-call diagnostic and the result

Exactly **one** `SetObjectToWorldMatrixFromEditor` call site in the Relay sources (`TransformApplier.cpp`), used by both modes; the M5 outfit setter is unchanged and unused in the runtime sequence. The `SMatrix` argument is reconstructed through the SDK's declared conversion `SMatrix(SMatrix43)` from the 12 words (axes with homogeneous `0.f`, translation with `1.f`); a 48-byte `SMatrix43` is never reinterpreted as a 64-byte matrix. The pre-call line uses the existing checked writer (`RelayLog::InfoChecked`): `command: <id> applying candidate.transform.set/1 mode <lift|restore> on frame <n>: candidate <entity> in <brick>; generation expected <g> fresh <g>; epoch <e>; link generation <l>; preimage world <W12> local <L7> parent <p> dirty 0; target world <W12>[; restore_of <id>]`; no call on a missing, failed or short write (`apply_log_unwritten`); an accepted line is a submission to the OS file cache, not power-loss durability. Fail-stop is real: `RelayLog::Guard` logs and propagates; a process termination or a lost result leaves BEAM with `unknown` and a possible effect; no catch-and-continue, no automatic retry.

The result separates: transport / authority status; `invocation` (`not_called` / `called` / `faulted`) and `setter_called`; `apply_log`; the generations (`expected`, `at_receipt`, `cached`, `fresh`, `post`) and epochs; `link_generation_at_call`; the identity block (`targets`, `cand_index_check`, `cand_resolved`, `cand_hitman5`, `cand_id_match`, `cand_distinct`, `cand_brick_owner`, `cand_spatial_distinct`, `registry_slots`); `preimage_world_words`, `preimage_local_words`, `preimage_parent`, `preimage_dirty`, `preimage_world`; `requested_world_words`, `requested_world`; `postimage_world_words`, `postimage_local_words`, `postimage_parent`, `postimage_dirty`, `postimage_world`; `post_same_entity` (the post read re-resolved the same entity); `world_match`, `local_match`, `hero_control` (12.8); the restore facts (12.9); `effect`; `precondition_ok`, `precondition_reasons`; `budget_remaining`, `mode`, `restore_of`. The reduction keeps every mandatory field (identity, the three exact groups, the generations, invocation, effect, apply_log, the restore facts); a result that cannot carry them is refused before invocation (12.3).

### 12.8 Effect rules, the dirty cache, controls and the comparison policy

- `effect = changed` **iff** the setter returned, the post read is available, `generation_post` equals `generation_fresh`, the post read resolved the same entity, `postimage_parent` equals `preimage_parent`, `postimage_dirty` is false and **all 12** postimage world words equal the requested words bit for bit. `unchanged` iff the same conditions hold with all 12 postimage world words equal to the preimage words. `uncertain` otherwise (a fault; a missing read; a generation, entity or parent change; a dirty post cache; neither match).
- `world_match`: `target` / `preimage` / `neither` / `indeterminate_dirty` (the post cache is dirty: the stored words are preserved as an observation but establish neither the target nor the baseline) / `unavailable`. `local_match`: `unchanged` / `changed` / `unavailable` (the post parent-relative group against the preimage group, bit for bit). Translation alone never decides anything.
- `hero_control`: the local hero's `W12`, `L7` and parent before and after the call: `unchanged` (bit-equal) / `within_tolerance` / `changed` / `unavailable`. An immediate control change other than `unchanged` is recorded and **invalidates the ledger** (no restore, no further write); it is never attributed to the candidate's setter.
- **Declared comparison policy**: bit equality is the only basis for `changed`, `unchanged`, `held`, `returned_to_baseline` and every `*_restored_exact` fact. The one numerical tolerance is **`k_DriftToleranceM = 1.0e-4`** per world word (metres for the translation, dimensionless for the axes), fixed and tested before runtime; agreement within it is labelled `near_target` / `near_baseline` / `within_tolerance` and is never called equality.
- **Later observations** (`relay.inspect.candidate_transform/1` on later frames; sampled states, never proof of continuous behaviour or of which system caused a change; `Command.TransformReadback.classify_later/3`): `held` (bit-equal to the requested group), `returned_to_baseline` (bit-equal to the preimage group), `near_target`, `near_baseline`, `drifted`, `indeterminate` (dirty cache), `unavailable`. An engine return to baseline is a distinct outcome from a commanded restore and is recorded as such. Nothing is written to fight an engine correction.

### 12.9 Restoration and the "no further writes after ambiguity" rule

- **Planning** (`Command.TransformRestore.plan/3`, from the verified journal file, as `Command.Reversal`): the original command's single `command.accepted` (mode `lift`), `transmitted`, `received` and one `terminal` in order, no `unknown` or refinement; the terminal `applied` with `effect = changed`, `world_match = target`, the preimage and postimage groups observed; the `peer.identified` entry naming the adapter; the journal open and the audit intact; the in-memory record agreeing. Then **`verify_inspection/4`**: a completed `relay.inspect.candidate_transform/1` later than the original's frame, on the same adapter, link and mission generation, within `reversal_inspection_max_age_ms` (60 s), with a clean cache, whose `cand_world_words` **equal the plan's postimage group**. If they equal the **preimage** group instead, the planner returns `{:error, :already_at_baseline}` and records that no explicit restoration call is needed — none is submitted to obtain a refusal. Drift, an indeterminate state, a changed parent or generation, or an ambiguous original effect stop effectful issuance; the saved matrix is never authority for an improvised recovery.
- **Issuance** (`Command.restore_candidate/2`): a fresh command id, fresh one-shot arming, `reversal_of` bound to the original and `reversal_inspection` to the inspection in the accepted entry; params `mode: restore`, `expect_world / expect_local / expect_parent` from the inspection, `target_world` from the plan's preimage, `restore_of` the original id. Native revalidates everything in 12.5–12.6 before the one setter call.
- **Restore facts in the result**, observed or unavailable, never inferred from the saved preimage: `world_restored_exact` (12 postimage words = the remembered preimage words), `local_restored_exact` (7 words; re-observed, never assigned), `parent_restored` (re-observed), `dirty_restored` (post dirty false), `snapshot_restored_exact` (all four), `world_within_tolerance` (numerical agreement). No raw field assignment, parent setter, cache update, physics setter, quaternion normalization write or second engine operation is added to force equality. Restoring observed transform values is not a rollback of physics, NPC perception, script, animation or other gameplay consequences.
