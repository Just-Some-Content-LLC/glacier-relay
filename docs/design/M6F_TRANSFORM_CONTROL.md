## 2. The reconciled schema (as implemented; design section 12)

**Snapshot** (`relay.inspect.candidate_transform` v1, no parameters, 31 native entries + 4 frame values = **35**; [S] measured 2,643 bytes of 4,096 on the fake present world (31 native entries + 4 frame values)): `generation_fresh`, `targets` (`007c57a6ea581f8c,feede715906f747f`), `snapshot_version` 1, the identity block (`cand_brick_present`, `cand_subentity_count`, `cand_index`, `cand_index_check`, `cand_resolved`, `cand_hitman5`, `cand_flags`, `cand_id_match`, `cand_distinct`, `cand_brick_owner`), `cand_spatial`, `cand_spatial_distinct`, `registry_slots`, `cand_in_registry`, `cand_world_words` (W12, 107 bytes), `cand_local_words` (L7, 62 bytes), `cand_dirty`, `cand_parent`, `cand_world`, `cand_local`, `cand_spatial_flags`, `hero_entity_id`, `hero_flags`, `hero_world_words`, `hero_local_words`, `hero_dirty`, `hero_parent`, `hero_world`. A word is the binary32 bit pattern as eight lowercase hex digits; a group is refused whole when a word is not eight hex digits, the count is wrong or a word is not finite; signed zero is preserved; nothing is decided from the seven-digit texts.

**Request** (`candidate.transform.set` v1; effectful, `token_verified`, mandatory `mission_generation`): `mode` `lift` | `restore`; `expect_world` W12, `expect_local` L7, `expect_parent` (16 hex or `none`) from a recent exact inspection; `target_world` W12 and `restore_of` UUID for a restore only. **Result** (47 entries; [S] measured 3,864 bytes for the fake lift): `mode`; the frame values; the five generations and two epochs; the identity block; `preimage_world_words` / `preimage_local_words` / `preimage_parent` / `preimage_dirty` / `preimage_world`; `requested_world_words` / `requested_world`; `postimage_world_words` / `postimage_local_words` / `postimage_parent` / `postimage_dirty` / `postimage_world` / `post_same_entity`; `world_match` (`target` / `preimage` / `neither` / `indeterminate_dirty` / `unavailable`), `local_match` (`unchanged` / `changed` / `unavailable`), `hero_control` (`unchanged` / `within_tolerance` / `changed` / `unavailable`); `restore_of`, `restore_facts` (`world=B,local=B,parent=B,dirty=B,snapshot=B,within_tol=B`); `link_generation_at_call`, `setter_called`, `apply_log`, `invocation`, `effect`, `precondition_ok`, `precondition_reasons`, `budget_remaining`, `reads_on_frame`. **Effect rules** [S]: `changed` iff the setter returned, the post read resolved the same entity, the generation held, the parent held, the post cache is clean and all twelve postimage words equal the requested words; `unchanged` iff the same with the preimage words; `uncertain` otherwise. A dirty post cache is `indeterminate_dirty`, never a match. The declared tolerance `k_DriftToleranceM = 1.0e-4` per world word labels `near_target` / `near_baseline` / `within_tolerance` only; bit equality alone decides `changed`, `unchanged`, `held`, `returned_to_baseline` and every `*_restored_exact` fact.

## 3. Operation and restoration limits (as implemented)

- **Native ledger** [S]: `forward_budget` 1 per process, consumed once the pre-call line was accepted and the call attempted — never by a refusal (a refused lift may be re-issued; the log-unwritten refusals leave it); one restore per forward (`already_restored`); the record invalidated by a fault, an uncertain / unchanged forward, a control change, a changed link or mission generation at the restore, or a lost record (a new process); then `operation_record_invalidated` / `operation_record_missing` / `restore_link_changed` / `restore_generation_changed` / `restore_target_mismatch` / `current_not_postimage` refuse everything with nothing called.
- **BEAM budget** [S]: one lift per authority process once a lift was accepted and its terminal is not a verified non-application (`applied`, `failed`, `unknown` and an in-flight lift consume it; `rejected` / `expired` / `precondition_failed` / `unavailable` leave it); `transform_budget_exhausted` names the consumer; fresh ids and repeated arming never produce a series of lifts; a restore is issuable only through `Command.restore_candidate/2` (the journal plan bound to a later exact inspection on the current link; `already_at_baseline` submits nothing; drift, a dirty cache, a changed parent, a changed generation, an unqualified candidate or an ambiguous original effect stop issuance); a hand-built restore is refused locally without the plan binding and natively against the record.
- **Restoration** [S]: the saved world group passes through the same single setter; the parent-relative fields, the parent and the dirty flag are re-observed, never assigned; `restore_facts` reports world / local / parent / dirty / snapshot / within-tolerance separately and only from the post read; no second engine operation forces equality; nothing rolls back physics, perception, script or animation.

- **Where the token resides:** in ONE private, unnamed ETS table (`Command.TokenHolder`) created by the authority in `init/1` — `:private`, not `:named_table`, no heir, owner the authority — as its single entry. - **Operations:** `open/1` (in the owner), `available?/1`, `verify/5` — no read operation. ### 14.3 The bounded follow-up sampler (`cmd-m6f.exs lift-follow` + `m6f_follow.exs`; commits `282b285`, `3b32fd7`)

**The arrangement chosen — the preferred shape, in the existing operator tool.** `lift-follow` is a new action of `cmd-m6f.exs`: one operator process that issues the one approved lift through the existing facade (`Command.lift_candidate/2`, behind the unchanged local guard over the qualifying exact inspection) and then runs a finite, read-only follow-up sequence through the existing public API (`Command.inspect_candidate_transform/1`, `Command.command/1`, `Command.observe/4`, `Command.status/0`, `Journal.status/0`). No in-node helper, no new service, no new observation command, no native change. Its VM is started by the run wrapper after the operator's go-ahead, so its startup (≈ 2.9–3.1 s of VM age at the send, measured) falls **before** the lift, never between the terminal and a read. The follow-up engine `M6fFollow` is a separate module that receives a client of read-only functions only: nothing in it can arm, lift, restore, reverse or set an outfit (a static test of its source, with positive controls, enforces that). Starting the action is the approved lift; loading the engine issues nothing; a separate operator process watching for the lift was rejected because it would have to infer which command to follow and adds a process to coordinate.

**Before the lift (all refusable, nothing issued):** a directory under a sealed root (it or an ancestor holds `sha256.txt`) and a label that already holds a capture this action writes are refused before anything is written; the arguments and the schedule are validated (≤ 6 strictly increasing offsets, windows, timeouts); the follow file `<label>-follow.ndjson` is created exclusively; the code the timed sequence uses is loaded; a cheap identity snapshot is taken (node, authority, journal, link, adapter and their state) and compared with the run's `ident-baseline.bin` when present (a log line says so when it is not); the unchanged lift guard runs, plus inert arming, no stop marker, a valid identity snapshot; only then is the `follow.plan` line written (its monotonic mark recorded; `follow.plan-armed-before-lift` is computed from that mark and the send's, not asserted), immediately before the lift is sent. A guard refusal leaves the follow file without a plan line.

**The sequence.** The lift's issuance is recorded at once, while it is in flight (`follow.issued`, the command-id file, the "lift issued" line). The engine then polls the lift's authoritative record; only an `applied` terminal is followed (failed / precondition_failed / expired / unknown: no read, no retry). The schedule: **slot 0 immediately when this process observes the terminal, then 250 ms, 1 s, 2 s, 5 s, 10 s after it** — target *request* deadlines on this process's monotonic clock, not native observation times. At most six requests, at most one in flight, an overall deadline (12.25 s after the terminal by default); a slot whose request cannot go out within its window (125 ms for slot 0; 250 ms for the later slots) is **missed** — recorded, never substituted; a request within its window but more than 25 ms late is **delayed**. Every follow-up RPC (the terminal polls, the inspections, `observe`, the identity snapshot) is bounded (2 s); the lift call itself and the record fetch after the schedule use the default, unbounded RPC. Each result is validated (same link, adapter and generation as the lift; the identity block equal to the binding inspection's; distinct and spatially distinct; in no registry slot; on one frame; not reduced; well formed), classified with the committed classes (`TransformReadback.classify_later/3`; a read on the lift's own or an earlier frame is `not_a_later_frame`) and journaled through `Command.observe/4`; one line per sample is appended to the follow file as it completes. Before each later slot: the stop marker and the identity snapshot. **Stops:** an operator stop (at the start of the terminal wait, every 250 ms while that wait lasts, before every later slot), a changed identity (node, authority, journal, link generation, adapter), a degraded audit, a refused / withheld / late / not-applied / reduced / malformed read, a changed context, an invalid identity, an aliased candidate, an unobserved qualification, an RPC failure, the overall deadline. A baseline return, a drift or a dirty cache is an observation; no result triggers any write. The sampler never invokes restoration.

**After the schedule (the deferred, heavyweight part):** the lift's 17 EVIDENCE lines (the shared `lift_report`, unchanged from the plain `lift` action), 14 follow EVIDENCE lines (plan armed before the lift; original applied; ≤ 6 requests; one in flight; no catch-up; the three early-sample targets; committed classes; journal agreement; only inspections accepted after the lift; every classified slot journaled; completed; evidence lines written), each sample's record and read-back under `<label>-s<N>-*` (so `xcheck.py --lift` and `restore-compare.py` run on them afterwards), and `<label>-follow-result.json` with the clock marks. **Clocks:** request lateness, request / receipt times and the terminal-observed time are this process's monotonic microseconds; native frame deltas and native timestamp deltas come from the native read-backs (one native process clock); the authority's stage ladder is the authority's; no difference between clocks of different processes is computed, and terminal-reception timing is kept apart from the setter's own frame and timestamp.

**What it cannot claim.** An RPC tool cannot guarantee the next engine frame: the earliest later observation is the first frame after the read reaches the native side. Its typical size is set mainly by the native link's idle result flush — `CommandLink.cpp` `ReadLines(50)`: a pushed result does not interrupt the 50 ms `select`, so the lift's own result waits up to 50 ms before it is sent (live in run 1: received 6 ms, applied 55 ms) — plus the round trip and the next frame. A return inside that interval cannot be told from a next-frame return; the tool identifies no writer and no cause. **Residuals:** a stop marker written within the last ≤ 250 ms of the lift's terminal wait still lets the one immediate, read-only request out (pinned by a deterministic test); a faulted lift is not followed even though the native reason says a later observation is required — any read after a fault is a separate operator decision (`ctransform`), as the fault is a hard stop.
