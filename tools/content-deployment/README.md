# Content-deployment tooling (M6-C)

Project-owned scripts for the controlled deployment of the historical Agent48 content into a HITMAN installation and for its
byte-identical removal, the independent verification of the generated packages, the scratch rehearsal of the install and
rollback, and the operator tooling of the attended runtime experiments. They were written and exercised in M6-C2
(`docs/design/M6C_CONTENT_DEPLOYMENT.md`, section 16) and committed here under the M6-C3 authorization, functionally identical to
the versions that passed M6-C2 apart from portability: every machine-specific absolute path became an explicit argument or a
documented environment variable (`config.example.sh`), and the relay node name is derived from the host. Nothing in this
directory is production code: the relay application under `relay/` and the native adapter are not changed by it.

Every script that touches a game installation takes the installation root as an explicit argument, writes only the files it
names, verifies every write by hash, refuses to overwrite an existing `patch300` package, and exits non-zero on any doubt.
A zero exit code is never the evidence; the written reports are. Pass absolute paths: the install, rollback and verify scripts
change into the tree they work on and open the expected-hash file and the baseline directory by the path given.

## Scripts

| Script | Purpose | Usage |
|---|---|---|
| `content-install.sh` | Installs exactly `Runtime/chunk0patch300.rpkg`, `Runtime/chunk27patch300.rpkg` (new) and `Runtime/packagedefinition.txt` (replaced after a two-copy backup). Before its first write it captures the replaced file's exact Windows timestamps into `<backup-dir>/timestamps.tsv` (`timestamps-capture.sh`); a failed capture aborts with nothing installed. | `content-install.sh <game-root> <artefacts-dir> <backup-dir> <expected.sha256>` |
| `content-rollback.sh` | Removes the two packages in whatever state they are (including `.installing` remnants), restores the package definition from a backup that matches `backup.sha256`, then restores its exact Windows timestamps from `timestamps.tsv` (`timestamps-restore.sh`) only after the bytes are verified. A missing manifest or any timestamp mismatch is a clear failure (exit 2) after the bytes are back. Idempotent. Does not depend on a normal game exit. | `content-rollback.sh <game-root> <backup-dir>` |
| `timestamps-capture.sh` | Captures the exact CreationTime / LastWriteTime (100-ns ticks), length and SHA-256 of named files under a root into a manifest, from the Windows side (`win-timestamps.ps1`). WSL's drvfs carries whole seconds only on `cp -p` and `touch`. | `timestamps-capture.sh <root> <manifest-out> <relative-path>...` |
| `timestamps-restore.sh` | Restores the manifest's timestamps: relative paths only, resolved under the root, each file's current content hash verified equal to the captured one first, the result read back and compared exactly. Use it for every file an installation replaces (`mods.ini` included). | `timestamps-restore.sh <root> <manifest>` |
| `win-timestamps.ps1` | The Windows-side helper behind the two scripts (`-Mode capture|restore`). Refuses absolute paths, parent references, wildcards and paths outside the root; touches nothing but the listed files' timestamps. | invoked by the scripts |
| `content-verify.sh` | Byte-identical restoration against a complete baseline: the full `Runtime` + `Retail` listing (sizes, mtimes), every Retail hash, the key files, the chunk0/chunk27 package hashes, no `patch300`, temporary or hitmen-named file. | `content-verify.sh <game-root> <baseline-dir>` |
| `game-tree-listing.sh` | Read-only listing (size, mtime, path) of `Runtime` and `Retail`. | `game-tree-listing.sh <game-root>` |
| `rehearsal.sh` | Ten install / rollback / verify cases on a scratch model of the game tree (copies of the three key files with deliberately nonzero sub-second timestamps, placeholders for the packages): normal, interrupted, missing artefact, partial failure, existing package, missing backup, repeated rollback, missing timestamp manifest, paths outside the root, and the generic capture / restore on `mods.ini`. The scratch root must be on a Windows filesystem. Never touches the real installation; its last line confirms that. | `rehearsal.sh <game-root> <artefacts-dir> <scratch-root> <real-baseline-listing.tsv> <report-file>` |
| `rpkg_read.py` | Independent RPKG reader (v1 `GKPR` and v2 `2KPR`, patch headers, the 8-byte XOR, pure-Python LZ4 block decoding) written from the public format source. | `python3 -I rpkg_read.py list <file> [--filter HEX,...]` / `extract <file> <HEX> <out>` |
| `verify-generated.sh` | The M6-C2 package verification: inventories, extraction, conversion with a project-built `ResourceTool.exe`, the structured and dependency comparisons of the Paris scene, the brick content check. Expects the M6-C2 evidence layout. | `verify-generated.sh <evidence-dir> <work-dir> <ResourceTool.exe>` |
| `run-deploy.cmd` | Runs the framework's `Deploy.exe` with console logging from the framework directory (used only with `outputToSeparateDirectory: true`; the framework must never be pointed at the game tree by this project). | `run-deploy.cmd <framework-dir>` |
| `provision-secret.sh` | One run-scoped 64-hex token at `<state-root>/token` (mode 600, ext4, never printed). | `provision-secret.sh <state-root>` |
| `start-beam.sh` (M6-F: optional third argument `effectful` starts the node with the effectful authority ON, the C-3 shape) | Starts the relay node for a controlled read-only run: recorder on, command subtree on, effectful authority OFF, token from the file, dashboard off, the in-node watcher `m5b_watch.exs` loaded. | `start-beam.sh <evidence-dir> <state-root>` |
| `m5b_watch.exs` | The in-node read-only watcher (session events, command status). | loaded by `start-beam.sh` |
| `cmd.exs` | The operator actions over RPC: `status`, `journal`, `linkcheck`, `arm`, `disarm`, `players [ttl|-] [recorded|empty]`, `entity [brick|-] [entity_id|-] [ttl|-] [absent|present]`, `outfit [cand|-] [gen|-] [ttl|-]`, and (M6-D1a) `candidate [brick|-] [entity_id|-] [ttl|-] [present|absent]` — `relay.inspect.candidate/1`, the read-only candidate-hero inspection whose packed groups are decoded by `GlacierRelay.Command.CandidateReadback` and logged with their statuses, and (M6-F) `ctransform [ttl|-] [present|absent]` — `relay.inspect.candidate_transform/1`, the read-only exact snapshot (the stored world and parent-relative transforms as binary32 words, decoded by `GlacierRelay.Command.TransformReadback`). `linkcheck` expects the six inert entries (M6-F) and no effectful entry advertised or claimed. Only inert public functions; no effectful action exists here (see `cmd-m6f.exs`). | `(cd relay && elixir --sname op-<label> -S mix run --no-start cmd.exs <evidence-dir> <label> <action> [args])` |
| `cmd-m6f.exs` | (M6-F) The effectful operator actions for the M6-F transform experiment over RPC: `status`, `journal`, `arm`, `disarm`, `ctransform [ttl|-]`, `attest <adapter> <ref>`, `own [exe]`, `arm-effectful [exe] [ttl]`, `lift <inspection_id> <gen> [ttl]` (the ONE compiled +0.25 world-z lift of the compiled candidate behind a local guard over the qualifying exact inspection — the expectation is that inspection's exact words, the target is computed natively, nothing else can be supplied), `plan-restore <id>`, `restore <id> <inspection_id> <gen> [ttl]` (only through `Command.restore_candidate/2`: the journal's plan bound to a later exact inspection; `already_at_baseline` submits nothing), `observe-later <id> <inspection_id> <text>` (the later class held / returned_to_baseline / near_* / drifted / indeterminate) and `observe`. Since the M6-F1a binding correction the lift and the restore pass the inspection's id and the issuing authority verifies it from its own journal (the `inspection_binding` of the accepted entry, `verified_by: "authority"`, is checked as EVIDENCE); the local guard is an early check only. Dry-run tested against the frozen M6-F1a probe; the run itself needs its own authorization. | `(cd relay && elixir --sname op-<label> -S mix run --no-start cmd-m6f.exs <evidence-dir> <label> <action> [args])` |
| `xcheck.py` | Cross-checks adjacent inspections (same frame source, frames advancing, identity stability, the candidate's presence and same-frame distinctness, slots recorded, slot 0 unchanged); with `--candidate C` (M6-D1a) the candidate inspection beside them (presence, lookup facts, flags and stored translation equal to the entity inspection's, the registry slots by identity against the players inspection's presence, the spawn facts recorded) and with `--prev-candidate PC` the identity elements against an earlier candidate result; with `--transform T` (M6-F) the exact-transform inspection beside them (word groups well formed, the hero's words against the entity rendering, the candidate qualified for a lift), with `--prev-transform PT` the words bit-equal / within tolerance / different, and with `--lift L` the later class of that inspection against a lift result. | `python3 -I xcheck.py <evidence-dir> <label> --players P --entity N [--candidate C] [...]` |
| `dry-run-m6c3.sh` | The offline dry run of the operator tooling against the frozen native command probe (no game, no DLL, ephemeral token). | `GLACIER_NATIVE_DIR=... dry-run-m6c3.sh <dry-run-evidence-dir> <throwaway-state-root>` |
| `run-probe-m6c3.cmd`, `tests-once-m6c3.cmd` | Windows-side launchers used by the dry run for the frozen probe and test executables. | see the scripts |
| `evidence-guard.sh` | (M6-D1b) The output-path guard a run's scripts source: the run root is created exclusively (`evg_claim`; an existing directory is refused, so a retry takes a new run identifier), every destination — WSL or Windows form, including those handed to `cmd.exe` / `powershell.exe` — is resolved physically (device:inode walk-up from the deepest existing ancestor) and must lie under the active run root or the declared state root (`evg_check`, `evg_win`), finalized captures are created exclusively (`evg_out`, no-clobber), live logs are checked (`evg_log`), a retried phase gets a fresh attempt directory (`evg_attempt`) and a reused capture label is refused (`evg_label`). Prior evidence roots are read-only inputs. It deletes, renames and truncates nothing and is not an evidence-storage subsystem. | `. evidence-guard.sh; evg_claim <run-root> [<state-root>]` / `evg_attach …` |
| `evidence-guard-selftest.sh` | Proves the guard on scratch directories only: historical destinations (WSL form, Windows form, `..` traversal, a symlink inside the active root, a short-name alias when the volume makes one) are refused before a sentinel changes; a claim of an existing directory, a reused label and a reused capture are refused with the earlier content unchanged; a retry gets a fresh attempt directory; a WSL subprocess, a `cmd.exe` script given the destination as its own argument and the PowerShell timestamp helper write exactly into the fresh destinations. | `evidence-guard-selftest.sh <fresh-scratch-base-on-/mnt/<drive>> <report-file>` |

## Configuration

See `config.example.sh`. The relay directory defaults to `../../relay` from this directory, the node name to
`relay@<host>`, the BEAM environment file to `~/.local/opt/beam-env.sh` (sourced when present). The dry run requires
`GLACIER_NATIVE_DIR` (the preserved, hash-verified native probe and test executables). The scripts are written for WSL on the
machine that hosts the game (`cmd.exe`, `tasklist.exe`, `wslpath`).

## What is not here

Generated game packages, decrypted or extracted proprietary game content, the third-party framework and its executables,
tokens, and the evidence of the runs. Those stay in the evidence directories described in the design records.
